# PKG-based architecture — MindFlow proof-of-concept

Демонстрация и измерение **Архитектуры #3 (Personal Knowledge Graph + EduKG)** на реальных пользователях MindFlow.

## Что собрано в эту итерацию

**Слой 1 — Aggregator** (`apps/api/src/llm/studentProfile.ts`):
- `buildStudentProfile(userId)` объединяет 5 источников: `personal_kg_nodes`, `kg_mastery_summary`, `math_topic_progress`, `mentor_messages`, `learning_plans`
- Возвращает `{strong, weak, recent, goal}` — выжимка для prompt
- `formatProfileForPrompt(p)` — короткий 5-7 строк блок
- `pickWeakInDomain(p, domain)` — фильтр слабостей по домену

**Слой 3 — PKG-driven генерация** (`apps/api/src/llm/personalizedExercises.ts`):
- `generatePersonalizedExercises(userId, domain, ...)` — главная функция use-case куратора
- Профиль → слабые концепты в домене → RAG retrieval → DeepSeek генерит 3-5 задач, направленных на gaps
- Опция `usePkg: false` — для A/B сравнения

## Что показала эта итерация

✅ **PKG-архитектура работает на реальных данных** — судья предпочитает персонализированные задачи когда у студента есть осмысленный профиль.

**Главное:** теперь у MindFlow есть прямая дорога от «знаем что студент путается в X» к «сгенерируем задачу про X для этого студента». До этой итерации все PKG-данные собирались, но обратно в pipeline не возвращались.

1. **BKT не работает** — `bkt_attempts = 0` в БД, поэтому `kg_mastery_summary` почти пуст. Сейчас профиль строится в основном из `personal_kg_nodes` (LLM-извлечение из диалогов) и `math_topic_progress`. Когда подключим BKT — сигнал станет точнее.

4. **Малый сэмпл** — 4 (user, domain) пары. Для статистической убедительности — нужно 30+.
