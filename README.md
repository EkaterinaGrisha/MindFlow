## Что это такое

MindFlow — это веб-приложение, в котором систематизированный теоретический контент по математике объединён с диалоговым AI-наставником, работающим по принципу «не решать за студента, а вести его к решению». Наставник:

- задаёт наводящие вопросы, предлагает прикладные кейсы и контраргументы;
- опирается исключительно на проверенный корпус учебных источников и сопровождает реплики ссылками на конкретные фрагменты;
- адаптирует подачу под текущее состояние знаний обучающегося, формализованное в виде графа концептов и байесовских оценок освоения.

Целевая аудитория — русскоязычные обучающиеся, осваивающие математический фундамент Data Science: студенты технических вузов, специалисты, переходящие в Data Science из смежных областей, и самостоятельные учащиеся.

## Ключевые возможности

| Возможность | Краткое описание |
|---|---|
| **Каталог учебных тем** | 24 темы по математике для Data Science (линейная алгебра, математический анализ, теория вероятностей, статистика, дискретная математика, численные методы), 10 из них — с расширенной интерактивной теорией с разобранными примерами и блоком самопроверки |
| **AI-наставник в 4 ролях** | LECTURER (объяснение), MIRROR (сократический диалог), SANDBOX (практический кейс), CHALLENGER (контрпример и проверка). Перед каждым ответом служебная роль-оркестратор выбирает педагогическую роль по контексту |
| **Гибридный RAG-поиск** | Плотный векторный поиск (эмбеддинги Qwen3-Embedding-0.6B, 1024d) + лексический BM25 + объединение через Reciprocal Rank Fusion + MMR-отбор разнообразных фрагментов. Обязательное цитирование источников в каждом ответе |
| **Модель знаний студента** | Граф из 44 концептов с пререквизитными связями + байесовское отслеживание освоения (Bayesian Knowledge Tracing, BKT) + персональный граф знаний из истории диалогов |
| **Адаптивная диагностика (CAT/IRT)** | Входной тест по схеме Computer Adaptive Testing на основе модели IRT 3PL: каждый следующий вопрос подбирается по максимуму информации Фишера при текущей оценке способности θ; обновление оценки — методом EAP |
| **Личные материалы (Pro)** | Загрузка PDF/DOCX обучающегося, индексация в изолированный персональный корпус, ответы наставника с опорой на личные документы |
| **Подписка** | 30-дневный пробный период + тариф Pro 349 ₽/мес. Защита разделов API проверкой статуса подписки |
| **Аналитика и обратная связь** | Plausible (privacy-first, без cookie) + Google Analytics 4 + серверный журнал событий + встроенный виджет NPS-отзывов |

## Архитектура решения

Программное решение организовано в форме монорепозитория. Центральный обработчик `/api/llm/respond` функционирует по шестиэтапной схеме:

```
запрос пользователя + контекст (тема, уровень, сводка по графу знаний)
   ↓
[1] Быстрый маршрутизатор (регулярные выражения):
    при распознавании запроса роль определяется немедленно
   ↓ (если запрос не распознан)
[2] LLM-оркестратор: классифицирует запрос и выбирает педагогическую роль
   ↓
[3] RAG-извлечение (retrieveRelevantChunks):
     • эмбеддинг запроса (локальная модель Qwen3-Embedding-0.6B, 1024d)
     • гибридный поиск (RRF: плотный + BM25, top-40 кандидатов)
     • ограничение на источник (≤ 2 фрагмента на один source_id)
     • MMR-отбор (баланс релевантности и разнообразия, λ ≈ 0,6)
   ↓
[4] Промпт под выбранную роль + извлечённые фрагменты → LLM (DeepSeek)
   ↓
[5] Ответ + цитаты (citations) + список использованных источников
   ↓
[6] Асинхронные побочные эффекты:
     • запись метрик извлечения
     • извлечение и сохранение концептов в персональный граф знаний
     • при наличии вердикта о правильности — пересчёт BKT-оценок
```

Архитектурный принцип: ни один ответ наставника не формируется исключительно из параметров языковой модели — каждому ответу предшествует этап извлечения фрагментов корпуса, и результат сопровождается явными цитатами.

## Технологический стек

| Слой | Технология | Краткое обоснование |
|---|---|---|
| Клиент | **React 19** + Vite + TypeScript + Tailwind CSS + KaTeX | Все ключевые потребности (markdown, KaTeX, drag-and-drop, графики) закрыты поддерживаемыми библиотеками экосистемы; Vite заменил deprecated CRA |
| Сервер | **Node.js 22** + Express + TypeScript (`tsx`) | Минималистичный слой под специализированный конвейер «оркестратор → поиск → LLM»; единый язык с клиентом через `packages/shared` |
| Хранилище | **Supabase** (PostgreSQL + pgvector + HNSW) | Консолидирует реляционное хранилище, аутентификацию, RLS и векторный поиск; гибридный поиск выполняется одним SQL-запросом |
| Языковая модель | **DeepSeek-V4-Flash** с каскадным резервом (Cloudflare Workers AI → OpenRouter) | Выбран по совокупности качества, скорости и стоимости на собственном бенчмарке 5 моделей нового поколения; на порядок дешевле проприетарных аналогов |
| Эмбеддинги | **Qwen3-Embedding-0.6B** (1024d), локально через `@huggingface/transformers` | Выбран по результатам сравнения 9 многоязычных моделей: NDCG@10 = 0.754, прирост +107 % относительно multilingual-e5-small. Локальный запуск устраняет тарификацию векторизации |
| BKT-моделирование | Python + numpy/scikit-learn (подпроект `services/adaptive-ml`) | Классический BKT с EM-калибровкой; на синтетических данных не уступает DKT при качественно меньшем числе параметров (96 vs 33 656) |
| Аналитика | Plausible + Google Analytics 4 | Dual-emit: приватная аналитика без cookie + детальная событийная аналитика |
| CI/CD | GitHub Actions, Railpack/Nixpacks | Lint + tests + build на каждое изменение; контейнеризация без ручного Dockerfile |

## Быстрый старт через Docker

Самый простой способ запустить проект целиком. Требуется только Docker (включая Docker Compose).

```bash
# 1. Скопировать шаблон переменных окружения
cp env.example .env

# 2. Заполнить минимум следующие переменные в .env
#    SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY    — для серверной части
#    VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY  — для клиента
#    DEEPSEEK_API_KEY                           — для языковой модели

# 3. Поднять стек (web + api)
docker compose up --build

# 4. Открыть в браузере
#    http://localhost:8080
```

Поднимаются два сервиса: API на `localhost:8787` и web (nginx со статической сборкой Vite + прокси `/api/*` на API-контейнер) на `localhost:8080`. База данных не поднимается локально — подключение к Supabase задаётся через переменные окружения.

При первом запуске API-контейнер скачивает модель эмбеддингов Qwen3-Embedding-0.6B (~1 ГБ) в персистентный том `hf-cache`. Последующие запуски используют кеш.

## Запуск без Docker (локальная разработка)

Требования: Node.js 22 (LTS), npm 10+.

```bash
# Установка зависимостей всех workspace
npm install

# Запуск клиента (Vite dev server, порт 3000)
npm run dev

# Запуск API (tsx watch, порт 8787) — в отдельном терминале
npm run dev:api

# Сборка production-артефактов клиента
npm run build
```

Для работы потребуется заполненный `.env` (см. ниже).

## Переменные окружения

Все переменные перечислены в `env.example`. Группы:

| Группа | Назначение | Где взять |
|---|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | Клиент-сайд подключение к Supabase (Auth + публичные таблицы под RLS) | Project Settings → API → Project URL и anon public key в [Supabase Dashboard](https://supabase.com/dashboard) |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Серверное подключение для серверных операций (минует RLS) | Project Settings → API → service_role secret |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_CHAT_MODEL` | Основная языковая модель | [platform.deepseek.com](https://platform.deepseek.com) → API Keys |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_MODEL` | Резервный LLM-провайдер при недоступности DeepSeek | Cloudflare Workers AI |
| `OPENROUTER_API_KEY` | Второй уровень резерва | [openrouter.ai](https://openrouter.ai) |
| `VITE_PLAUSIBLE_DOMAIN` | Подключение приватной аналитики Plausible | Имя домена в [plausible.io](https://plausible.io) |

Минимально достаточный набор для запуска и работы RAG-конвейера: Supabase + DeepSeek. Резервные провайдеры опциональны.

## Загрузка учебного корпуса

В репозитории присутствует `infra/data/rag_manifest.json` со списком источников. Сами PDF-файлы учебников не включены по соображениям авторского права. Чтобы воспроизвести корпус:

```bash
# 1. Скачать PDF учебников в infra/data/ (см. textbooks_sources.csv)
# 2. Запустить ингест (требует заполненного .env с Supabase service_role key)
npx tsx infra/ingest/ingest.ts
```

Скрипт извлекает текст из PDF, разбивает на фрагменты, вычисляет эмбеддинги локально через Qwen3-Embedding-0.6B и сохраняет в таблицу `rag_chunks` Supabase.

Альтернатива — использовать собственный корпус: добавить источники в `rag_manifest.json` и запустить ингест.

## Тесты и непрерывная интеграция

```bash
# Все тесты (api, llm, ingest)
npm test

# Только тесты выбора педагогической роли
npm run test:llm-routing -w @mindflow/api

# Интеграционные тесты API
npm run test:integration -w @mindflow/api

# Python-тесты подготовки корпуса
npm run test:rag-corpus
```

Покрытие:

| Каталог | Что проверяется |
|---|---|
| `tests/api/` | health-эндпойнт, RAG-поиск, rate-limiter, разбор вердикта о правильности ответа |
| `tests/llm/` | оркестрация педагогических ролей, граница RAG (MMR, фильтр артефактов) |
| `tests/ingest/` | разбор кодировок, корректность ингеста |

Непрерывная интеграция (`.github/workflows/ci.yml`): на каждый push в `main` и pull request на Ubuntu с Node.js 22 последовательно выполняются `npm ci` → `npm run lint` (tsc --noEmit) → `npm test` → `npm run build` с таймаутом 15 минут.

## Подпроект `services/adaptive-ml`

Python-реализация байесовской модели отслеживания освоения (BKT), нейросетевой альтернативы (DKT, Piech-style LSTM) и рекомендательного компонента. Используется для офлайн-калибровки параметров `bkt_concept_params` в основной базе данных.

```bash
cd services/adaptive-ml
python3 -m pip install -r requirements.txt   # numpy + scikit-learn + torch
python3 run_baseline.py                      # BKT baseline
python3 run_dkt.py                           # DKT baseline
python3 run_recommender.py                   # сравнение рекомендательных стратегий
python3 -m unittest discover tests           # юнит-тесты
```

Результаты сохраняются в `services/adaptive-ml/results/`.
